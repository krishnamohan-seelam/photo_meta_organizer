Prototype C · Console

Built for people who treat the library as data: a token query bar, facets that double as charts, a sortable table and an inspector that shows the raw record. Dense, fast and keyboard-first, like an IDE for your photos. ← All prototypes

1 · Search box → token query bar

Before
The Ctrl+K trigger is a fake input, and filters live in sidebar checkboxes, so you can't type "Sony shots above ISO 1600".
After
Type camera:sony iso:>=1600 tag:night. Each clause becomes a removable token, and autocomplete suggests fields, then values with live counts. Backspace removes the last token; plain words become free-text tokens.
Why
Camera, tag, rating, pick, date and text tokens map onto the existing POST /api/search request, so power users can skip the mouse. The ISO, aperture and focal ranges shown here are aspirational: they need new API fields (see design_docs/front_enddesign.md §9).

2 · Filter sidebar + Analytics view → facet panel

Before
Checkbox lists with counts in brackets, and distributions hidden in a separate Analytics tab.
After
Each facet (camera, lens, ISO band, focal band, aperture band, rating, capture month) shows a bar per value. The grey bar is the whole library and the coloured bar is the current result. Clicking a row adds the matching token.
Why
You see the shape of the data while you filter, for example "most night shots are from the GR III". GET /api/facets already returns most of these counts.

3 · Gallery → table/grid toggle

Before
One card grid. Comparing exposure settings across photos means clicking each one.
After
A dense table with sortable columns (camera, lens, focal length, aperture, shutter, ISO, date, rating, size) and right-aligned tabular numbers. Shift-click selects a range, Ctrl-click toggles a row, and J/K move. The grid layout stays one click away.
Why
A table is the right tool for comparing metadata. It also virtualizes trivially (fixed 38px rows) for libraries of 100k photos.

4 · Inspector → tabbed Summary / EXIF / JSON

Before
One long panel. Raw JSON only reaches the clipboard, unseen.
After
Summary has the preview, curation and four key numbers. EXIF has grouped key/value rows with copy on hover. JSON shows the exact API record with syntax highlighting.
Why
It shows information in layers: casual users stay on Summary, and debugging an extraction issue means opening the JSON tab.

5 · Header progress → status bar

Before
JobProgress replaces the Scan/Sync buttons in the header while a job runs.
After
A status bar like an IDE's: database, library totals, selection count and size, job progress, and quick Sync.
Why
Background work stays visible without moving the header around, and the status bar is a natural place for desktop-app status.

6 · Command palette exposes the CLI

Before
prune, dedupe and sync --rehash exist only in the CLI.
After
Every command appears in Ctrl+K with its CLI equivalent shown next to it.
Why
Parity between the CLI and the UI, and it teaches the CLI to people who want to script it.

Adopting it in the React code

Add QueryBar.tsx with a pure parseQuery()/toSearchRequest() in utils/search.ts (easy to unit-test with Vitest). Use a new PhotoTable.tsx with TanStack Virtual (already a dependency). The facet panel reuses useFacets. Add StatusBar.tsx using useJobs. Extend CommandPalette.tsx with job commands. Effort: medium. It is the closest match to the current component structure.
